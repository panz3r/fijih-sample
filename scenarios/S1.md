# S1. Happy path

Exercises Preflight, Plan, Implementation (automatic approval), Local QA review, Delivery with a changeset, the Copilot pass, Ready-for-review, QA approval, the Jira handoff comment, Cleanup, and post-cleanup reverification.

## Jira issue

- Type: Story
- Summary: Add tags to bookmarks

```jira
h2. Context
Users want to group bookmarks. A bookmark gets an optional list of tags; the API accepts and returns them, and the page shows them next to the title.

h2. Acceptance criteria
* POST /bookmarks accepts an optional "tags" array of strings; each tag is trimmed, lower-cased, and deduplicated; an empty array is the default.
* A tag longer than 32 characters or containing whitespace answers 400 with {"error":"invalid tag"}.
* GET /bookmarks returns the tags of each bookmark.
* The web page shows each bookmark's tags after its title, comma separated, and shows nothing when there are none.
* Unit tests in packages/shared, packages/api, and packages/web cover the new behaviour.

h2. Decisions
* Tags are not filterable yet.

h2. Out of scope
* Filtering or searching by tag.
* Editing tags of an existing bookmark.
```

## Precondition

`scripts/reset`.

## Expected checkpoints

1. `plan-approval`: a work item with five criteria mapped to tasks across the three packages, Operational Requirements naming the `main` ruleset's required `test` check with read-only evidence, no open questions (the issue settles the decisions). Approve.
2. `implementation-approval` is not presented: all validations pass, no user questions, so Local QA review starts directly.
3. `local-qa-review`: gate `pass` or `concerns`, with the implementation summary. Approve.
4. Delivery: a `.changeset/*.md` whose summary is "Add tags to bookmarks", a draft pull request titled `[<KEY>] Add tags to bookmarks` labelled `enhancement`, Copilot review requested. Copilot pass resolves any finding.
5. `ready-for-review`: approve. The pull request becomes ready; review is requested from `fijih-qa-bot`.
6. Run `scripts/review-as-qa <pr> approve`.
7. `jira-handoff`: the draft names the "not filterable yet" decision and the out-of-scope items. Approve.
8. Cleanup deletes the work item in one push; reverification is clean; the run ends with the wrap-up offer.
