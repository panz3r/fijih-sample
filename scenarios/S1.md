  type: Story
  summary: Add tags to bookmarks
  description: |
    h2. Context
    Users want to group bookmarks. A bookmark gets an optional list of tags; the API accepts and returns them, and the page shows them next to the title.

    h2. Acceptance criteria
    * POST /bookmarks accepts an optional "tags" array of strings; each tag is trimmed, lower-cased, and deduplicated; an empty array is the default.
    * A tag longer than 32 characters or containing whitespace answers 400 with {"error":"invalid tag"}.
    * GET /bookmarks returns the tags of each bookmark.
    * The web page shows each bookmark's tags after its title, comma separated, and shows nothing when there are none.
    * Unit tests in packages/shared, packages/api, and packages/web cover the new behaviour.

    h2. Decisions
    * Tags are not filterable yet.

    h2. Out of scope
    * Filtering or searching by tag.
    * Editing tags of an existing bookmark.

# S1. Happy path

Exercises Preflight, Plan, Implementation (automatic approval), Local QA review, Delivery with a changeset, the Copilot pass, Ready-for-review, QA approval, the Jira handoff comment, Cleanup, and post-cleanup reverification. The first run to make after any FIJIₕ change.

## Precondition

- `scripts/reset`

## Run

1. `plan-approval`. **Expect:** a work item with five criteria mapped to tasks across the three packages, Operational Requirements naming the `main` ruleset's required `test` check with read-only evidence, and no open questions (the issue settles the decisions). Approve.
2. **Expect:** `implementation-approval` is not presented: all validations pass and there are no user questions, so Local QA review starts directly.
3. `local-qa-review`. **Expect:** gate `pass` or `concerns`, with the implementation summary. Approve.
4. Delivery. **Expect:** a `.changeset/*.md` whose summary is "Add tags to bookmarks", a draft pull request titled `[<KEY>] Add tags to bookmarks` labelled `enhancement`, and Copilot review requested. The Copilot pass resolves any finding.
5. `ready-for-review`. Approve. **Expect:** the pull request becomes ready and review is requested from the QA Engineer (`duckyduff369`).
6. `scripts/review-as-qa <pr> approve`.
7. `jira-handoff`. **Expect:** the draft names the "not filterable yet" decision and the out-of-scope items. Approve.
8. **Expect:** Cleanup deletes the work item in one push, reverification is clean, and the run ends with the wrap-up offer.

## Reset

- `scripts/reset` (closes the pull request)
