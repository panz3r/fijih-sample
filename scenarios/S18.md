# S18. Base moved after Cleanup

`main` moves while the run waits at `jira-handoff`: Base Sync for a mergeable pull request; for a conflicting one, Base Sync resolves the conflicts only when the answer asks for it, and the resolved merge stays local until it is approved at `base-merge-review`.

FIJIₕ tells a resolved merge from a clean one with `git show --remerge-diff`, which prints every change a merge makes beyond Git's own merge. The work item is already deleted at that point, so the unpushed resolved merge is the checkpoint's only state: a run resumed later presents it again rather than pushing it.

## Precondition

- `scripts/reset`

## Run

1. While the run waits at `jira-handoff`, open and merge a second pull request on `main` that edits `packages/api/src/store.ts` near the tag validation (admin bypass). For the conflicting variant, edit the line in `add()` that builds the stored bookmark, which the work item's change also edits; the pull request then reports `CONFLICTING`.
2. Approve the handoff. **Expect:** post-cleanup reverification reports the moved base. A mergeable pull request gets the Base Sync offer. A conflicting one blocks with the question to merge `main`, saying the merge will conflict and that Base Sync can resolve it for review before anything is pushed.

### (a) Conflicting: Base Sync resolves

3. Answer "merge main and resolve the conflicts". **Expect:** Base Sync runs on the `standard` tier, keeps both changes in `store.ts`, runs the project's validations, and leaves the merge unpushed (the pull request head is still the cleanup commit). The `base-merge-review` checkpoint shows the merge commit with its two parents, the remerge diff of `store.ts`, each validation, the QA approval the push may dismiss, and whether the posted Jira handoff comment states anything the merge changed (a correction comment is drafted only then).
4. Approve pushing the merge. **Expect:** the merge is pushed (on the `light` tier), the pull request description notes the merged change, post-cleanup reverification passes with CI green on the merge, and the run ends with the pull request mergeable.

## Reset

- `scripts/reset`
