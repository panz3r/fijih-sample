# S21. Post-cleanup reverification watches a running check

Cleanup's push leaves the required `test` check running, and reverification must watch it rather than return `blocked`.

Reverification waits only when no counted run has decided a required check: when Cleanup's push cancels the run on the last commit that changed more than the work item. A completed run on that commit decides the check, so the delay alone is not enough; the re-run in step 2 is what Cleanup's push cancels, through the workflow's `concurrency` group.

## Precondition

- `scripts/reset`
- `gh variable set CI_DELAY_SECONDS --body 120`, so the required `test` job sleeps first. Keep the delay under 15 minutes, the reverification watch limit.

## Run

1. Run S1 to the `jira-handoff` checkpoint. **Expect:** pushes only at Delivery (and a Copilot fix, if any), with no run cancelled before Cleanup.
2. At `jira-handoff`, re-run the `ci` run of the last code commit (`gh run list --branch <branch>`, then `gh run rerun <run id>`) and approve while its `test` job is still sleeping. **Expect:** Cleanup's push cancels that re-run.
3. **Expect:** post-cleanup reverification finds the re-run cancelled and the cleanup head's `test` still running, watches it instead of returning `blocked`, reads mergeability again when the watch ends, and returns `ready` without the user saying CI finished.
4. **Expect:** Delivery, Ready-for-review, and Record commit subjects follow the commit convention of `AGENTS.md`, never an `Approved:` Change Log entry.

## Reset

- `gh variable set CI_DELAY_SECONDS --body 0`
- `scripts/reset`
