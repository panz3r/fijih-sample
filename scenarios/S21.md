# S21. Post-cleanup reverification watches a running check

Issue: S1. Before the run, slow the required `test` job: `gh variable set CI_DELAY_SECONDS --body 120`. Keep the delay under 15 minutes, the reverification watch limit.

Reverification waits only when no counted run has decided a required check: when Cleanup's push cancels the run on the last commit that changed more than the work item. A completed run on that commit decides the check, so the delay alone is not enough. At the `jira-handoff` checkpoint, re-run that commit's `ci` run (`gh run list --branch <branch>`, then `gh run rerun <run id>`) and approve while its `test` job is still sleeping. Cleanup's push then cancels it through the workflow's `concurrency` group.

Expect:

- Pushes only at Delivery (and a Copilot fix, if any) and at Cleanup, with no run cancelled before Cleanup.
- Post-cleanup reverification finds the re-run cancelled and the cleanup head's `test` still running, watches it instead of returning `blocked`, reads mergeability again when the watch ends, and returns `ready` without the user saying CI finished.
- Delivery, Ready-for-review, and Record commit subjects in the commit convention of `AGENTS.md`, never an `Approved:` Change Log entry.

Reset with `gh variable set CI_DELAY_SECONDS --body 0` and `scripts/reset`.
