# S7. Human review remediation

A review thread, a changes-requested review, a review-body finding, and the approval, all posted as the QA Engineer.

## Precondition

- `scripts/reset`
- `QA_GH_TOKEN` set

## Run

1. Run S1 through `ready-for-review` and approve it, but do not approve as QA yet.
2. `scripts/review-as-qa <pr> thread packages/api/src/store.ts <line of the tag validation> "Please reject an empty-string tag explicitly."`, then `scripts/review-as-qa <pr> request-changes "Tags should be sorted alphabetically in the response."`.
3. **Expect:** the orchestrator suspends into Review remediation: the thread is fixed and resolved with a reply citing the commit; the sorting request is classified `clarification-required` because it adds a criterion, with a question under `risks`; the `review-remediation` checkpoint is presented because a `clarification-required` finding remains.
4. Answer "yes, sort tags alphabetically" (an Inline scope change). **Expect:** an Implementation re-entry with reason `user-request`.
5. `scripts/review-as-qa <pr> approve-with-request "Approving. Please also mention the tag limits in the README before merging."`. **Expect:** a review-body finding keyed `<review ID>#1`, answered in a conversation comment, with the README change or an explicit disposition.
6. **Expect:** Jira handoff proceeds once the approval rule (one approval from the QA Engineer) is met.

## Reset

- `scripts/reset`
