# S9. Two stacked work items for one issue

- Type: Story
- Summary: Export bookmarks as CSV

```jira
h2. Context
Users want to export their list. Two pull requests: the API endpoint first, then the web button stacked on it.

h2. Acceptance criteria
* GET /bookmarks.csv answers text/csv with a header row and one row per bookmark (title, url, createdAt), newest first.
* The web page has an Export button that downloads /bookmarks.csv.
* Tests cover the endpoint and the button.

h2. Decisions
* Work item split: "api" (endpoint) and "web" (button), the web item stacked on the api branch.
```

Expect the first work item `<KEY>`, the second `<KEY>-web` with `artifacts.base_branch` set to the first item's branch, a stacked pull request, and, once the first pull request merges (this scenario merges it), the `base-retargeted` transition. Precondition `scripts/reset`; reset merges nothing back, so run `scripts/reset` at the end.
